# 故障排查手册（TROUBLESHOOTING）

> 收录真机验证过的高频坑，按症状分类。每条给「症状 → 根因 → 自救步骤」。
> 找不到你的问题？到 [Issues](../../issues) 提问时附上：版本号（设置 → 关于）、`logs/` 下相关日志、复现步骤。

---

## 一、安装 / 启动

### 1. 装完能打开，但全局热键 / 系统监控 / 游戏 Agent 等功能"没反应"
- **根因**：0.2.7 之前的安装包缺 23 个第三方依赖（打包清单缺失，功能静默失效）。
- **自救**：到 [Releases](../../releases) 升级到 ≥0.2.7。0.2.7 起安装包带依赖守卫（构建期校验 30 个模块可导入），此类问题不会再静默出现。

### 2. 设置 → 关于显示 `v0.0.0-dev`
- **根因**：旧版安装包资源清单不全，后端读不到 `version.json`（0.2.9 之前的历史问题）。
- **自救**：升级到 ≥0.2.9。侧边栏版本号与顶部栏版本号会一致显示。

### 3. SmartScreen 提示「未知发布者」
- **根因**：安装包使用**自签名证书**（未购置受信任 CA 的 OV/EV 证书），自签名的根不被 Windows 信任，**预期行为、不是被篡改**。
- **自救**：点「仍要运行」前，先按 README「安全与完整性」做 SHA-256 校验；也可下载 `naixi-selfsign.cer` 导入受信任根后，在安装包属性的「数字签名」里核验主体与指纹。

### 4. 安装或启动时杀毒软件报警
- **根因**：安全中心的急救能力（结束进程 / 删计划任务 / 改 Defender 排除项）可能被其他杀软误报；自签名（无受信任证书链）也常触发启发式。
- **自救**：确认安装包哈希与官方 `SHA256SUMS.txt` 一致后，在杀软中加白或信任。

## 二、语音（最易误判，先分清"哪条链路没声"）

### 5. 完全没有声音（对话页日志全绿）
- **先查引擎状态**：`http://127.0.0.1:9845/api/live/status` 看 `running` 是否为 `true`——引擎未启动时语音请求只入队、永不消费，日志看起来一切正常。
- **再查浏览器自动播放拦截**：打开开发者工具（F12）看 Console 是否有 `[语音] 播放失败`；有则点击一次页面（任意手势）解锁 AudioContext 即可。

### 6. 对话有声音、弹幕直播没声音（或反过来）
- **根因**：全局 TTS 与弹幕 TTS 是**两套独立配置**（全局走 `tts_mode/tts_voice`，弹幕走 `live_config` 的 `tts_model/tts_voice/tts_engine`），互不相通；且音色与模型必须同家族。
- **自救**：对拍 `/api/live/config` 与 `/api/config/tts` 两处配置，确认模型/音色匹配。

### 7. 云端 TTS 突然变成"机器味"（像浏览器朗读）
- **根因**：云端 TTS 鉴权失败（401/403）时**静默降级**到 Edge-TTS，听感变化但不会报错弹窗。
- **自救**：看日志搜 `[TTS降级]`，或用 `POST /api/live/test-tts` 复测；多为 API Key 过期/欠费，重新配置即可。

## 三、桌宠 / 渲染

### 8. VRM 模型腿不动、动作僵硬
- **根因**：MMD 转制的模型是"双骨骼 rig"（动画驱动 control 骨骼、网格权重在 deform 骨骼），旧版只驱动了其中一套。
- **自救**：升级到 ≥0.2.8（已内置 `_fixDualBoneRig()` 自动修复）。

### 9. 摄像头面捕开了没反应
- **根因**：面捕**默认关闭且禁止自启动**，必须从桌宠右键菜单手动开启；开启后摄像头指示灯亮起才是真在工作。
- **自救**：右键桌宠 → 开发者模式/面捕相关菜单项勾选开启。

### 10. GPU / 显卡显示「未检测到」
- **根因**：虚拟机（无 GPU 直通）或核显环境下取不到独立显卡信息，**属正常现象**，不影响对话等核心能力。

## 四、搜索 / 网络

### 11. 搜索结果变少或变慢
- **根因**：内置 SearXNG 未就绪时自动降级到公共引擎（离线也降级），**属预期行为**。
- **自救**：等启动看门狗自动拉起 SearXNG（日志可见）；确认无端口冲突（SearXNG 独立端口）。

### 12. 后端连不上（前端一直转圈）
- **根因**：后端绑 `127.0.0.1:9845`，端口被占用或 sidecar 未启动。
- **自救**：`netstat -ano | findstr 9845` 查占用；重启应用（看门狗会拉起后端）。

## 五、数据

### 13. 升级后想确认数据还在
- 数据全在安装目录 `data/`（SQLite 主库 + 文件）；升级覆盖安装不针对它做格式化。**升级前手动备份 `data/` 目录最稳妥。**

### 14. 想彻底清空重来
- 关闭应用（托盘退出），删除 `data/` 目录后重启，即得全新空库（各表 count=0 的全新装机状态）。

## 六、虚拟机 / 远程桌面

### 15. 虚拟机里点「桌宠」没反应，桌面一片空白
- **症状**：VMware / 远程桌面里启动 3D 桌宠，进程确实起来了（任务管理器能看到 `pythonw.exe`），但屏幕上什么都看不到；切到 2D 又提示「还没有模型」。
- **根因**：3D 桌宠走 Chromium 的 WebGL 渲染。两件事凑在一起导致 WebGL 上下文创建失败 —— ① Chromium 自 M117 起**默认禁止**在拿不到硬件 GL 时回退到软件渲染（SwiftShader）；② 虚拟机显卡驱动常被 Chromium 的 **GPU 黑名单**拦下。上下文建不出来 → 页面脚本整体中断 → 窗口全透明。**1.0.0 及更早版本没有把这层失败告知用户**，所以表现为"点了没反应"。
- **自救**：升级到 ≥1.0.1。1.0.1 起桌宠启动时自动注入 `--ignore-gpu-blocklist --enable-unsafe-swiftshader`（放行黑名单 + 允许软件渲染兜底）。真机实测：同一台 VMware 上，加这两个参数前一直 `JS-NOT-RUN`、窗口全透明；加之后 `[PROBE] READY`、26–44 FPS、形象正常显示。
- **仍然空白时按顺序查**：
  1. VMware 显示设置确认勾选「加速 3D 图形」，显存给到 1 GB 以上；
  2. 打开 `%APPDATA%\奶昔\logs\pet_vrm.log`，搜 `[PROBE] webview status`：只有 `READY` 才代表渲染就绪（`JS-NOT-RUN` = 页面脚本没跑起来）；
  3. 若桌宠窗口里出现提示卡「3D 形象渲染不可用」，按卡上两条出路处理（装/更新显卡驱动，或切 2D）；
  4. 切 2D 后提示「还没有模型」是**正常**的 —— 说明本机确实没有 Live2D 模型，在「还没有模型」卡片上点一下导入 `.model3.json` 即可。

## 七、出现多个实例 / 「点了没反应」

### 16. 任务管理器里有好几个奶昔（多个 `naixi-desktop.exe`、多个 `pythonw.exe`）
- **症状**：界面「点了没反应」、某些功能时好时坏、后端 PID 会莫名变化、桌宠切换偶尔失败。
- **根因**：**1.0.1 之前没有单实例保护** —— 双击两次图标（或安装后手动又启动一次）就会起**两套完整实例**：两个主程序、两个后端、两套 SearXNG。两个后端会争抢 `9845` 端口，于是出现「某个实例连着的后端被另一个实例关掉」的错乱。
- **自救（1.0.1 之前）**：先全关掉再只开一个 —— 托盘右键退出，然后到任务管理器结束所有 `naixi-desktop.exe` 与路径含 `奶昔\resources` 的 `pythonw.exe`，确认 `9845` 端口不再被监听，再重新启动。
- **1.0.1 起**：已加单实例守卫。再次双击图标不会新开实例，而是**把已在运行的窗口唤到前台**；启动时若发现端口被上次残留的自家后端占着，会先清理它再拉起，不再出现两个前端共用一个后端的情况。
- **顺带一条自查**：如果某次操作后整个界面卡住、多个接口同时超时，那不是网络慢，而是某个接口占住了后端的事件循环（1.0.1 已修掉两处：切换 3D 桌宠、安全扫描 / 一键急救）。
